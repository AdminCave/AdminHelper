### T1 — R-0530: die Skripte lesen die `.env` byte-treu (`LC_ALL=C grep -a`)  [ ]
Komponente: scripts · Dateien: scripts/init-secrets.sh, scripts/install.sh, scripts/update.sh, scripts/tests/init-secrets_test.sh, scripts/tests/install_test.sh, scripts/tests/update_test.sh, CHANGELOG.md
Änderung: GNU grep hält eine Datei für binär, sobald sie ein NUL-Byte oder ein in der Locale des Aufrufers ungültig kodiertes Byte enthält, und unterdrückt dann Ausgabezeilen; der Exit bleibt 0, die Meldung „binary file matches“ geht nach stderr (`man grep` 3.11, `--binary-files`). Unter einer UTF-8-Locale fehlt so jede Zeile mit einem Latin-1-Byte, bei einem NUL-Byte irgendwo in der (kleinen) `.env` fehlt jede Zeile, in jeder Locale. Folgen heute: `upsert`/`upsert_env` schreiben die `.env` ohne diese Zeilen zurück (`init-secrets.sh:63`, `install.sh:195`, `update.sh:191`), ebenso die Wiederherstellung der Image-Pins im Rollback (`update.sh:602-603`); `is_set_safely` (`init-secrets.sh:37`) liest einen gesetzten Wert als leer, und `init-secrets.sh` erzeugt ihn neu, auch `POSTGRES_PASSWORD` und `CA_ROOT_PASSPHRASE`; `installed_version`/`installed_label` (`update.sh:201`, `:215`) finden bei einem NUL-Byte kein `SERVER_IMAGE` und nehmen einen Floating-Tag an. Schreibweise mit eigenem `-a` vor dem bisherigen Flag (`grep -a -vE`, `grep -a -qE`, `grep -a -E`): die grep-Wrapper der Tests erkennen ihren Aufruf an `-vE ^#?…` bzw. `-qE ^#?…` (`init-secrets_test.sh:75`, `install_test.sh:65`, `update_test.sh:96`, `:98`). ### T2 — R-0538: die Skripte ersetzen eine schreibgeschützte Datei ohne Rückfrage (`mv -f`)  [ ]
Komponente: scripts · Dateien: scripts/init-secrets.sh, scripts/install.sh, scripts/update.sh, scripts/tests/init-secrets_test.sh, scripts/tests/install_test.sh, scripts/tests/update_test.sh, CHANGELOG.md
Änderung: GNU mv fragt nach, wenn das Ziel existiert, nicht schreibbar ist, stdin ein Terminal ist und `-f` fehlt; ohne Antwort wartet es, eine verneinende Antwort lässt die Datei aus (coreutils-Handbuch, „mv invocation“). Betroffen ist jeder `mv`, der eine Datei der Installation ersetzt: `init-secrets.sh:65`, `install.sh:197`, `update.sh:193`, `:489`, `:514`, `:604`. Mit einer schreibgeschützten `.env` (oder Laufzeit-Datei) und einem Terminal auf stdin wartet das Skript heute auf eine Antwort; unter einem Wrapper, der stderr einsammelt, sieht niemand die Frage, und es hängt. Neu mit `-f` (`mv -f`, `mv -fT`). Den Modus einer schreibgeschützten `.env` behalten die Skripte schon heute nicht (`chmod 600` in `init-secrets.sh:109`, `install.sh:243`, `update.sh:565`); es entfällt nur die Frage. Der mv-Wrapper in `update_test.sh:153-167` erkennt den Tausch der `.env.example` am wörtlichen Argument (`:161`, `-T .env.example.ah-new .env.example`) und zieht mit der neuen Schreibweise mit; der Kommentar zu Test 38 (`:1031-1033`) nennt `</dev/null` danach nicht mehr als Schutz vor der Frage. Tests zuerst rot, je Fall unter einem Pseudo-Terminal ohne Eingabe und mit `timeout` (z. B. 60 s): `script -qec "<befehl>" /dev/null` aus util-linux, dessen stdin ein Prozess ist, der länger lebt als der `timeout` (`< <(sleep …)`; mit stdin `/dev/null` reicht `script` ein EOF weiter, und mv lässt die Datei aus, statt zu warten). Fehlt `script`, oder binden Dateirechte den Nutzer nicht (root; Probe wie `update_test.sh:1019-1020`), sind diese Fälle ein SKIP: Exit 75 am Ende des Tests, nicht grün. Rot heißt Exit 124 oder eine ausgelassene Datei. (a) `init-secrets_test.sh`: `.env` 0444 mit leerem `SECRET_KEY` → Exit 0, `SECRET_KEY` erzeugt, Modus 600. (b) `install_test.sh`: Checkout-Modus wie Test 5 mit `.env` 0444, `--domain … --admin-password … --yes` → Exit 0, `DOMAIN` neu. (c) `update_test.sh`, neuer Abschnitt hinter dem aus T1: Update 0.33.0 → 0.34.0 mit `.env` 0444, die `NEW_FEATURE_FLAG=on` schon trägt (die Migration hängt nichts an, `upsert_env` ersetzt die Datei) → Exit 0, Pins 0.34.0; Test 38 „append“ unter dem Terminal (Rollback vor dem Deploy, `:489`) → Exit ≠ 0 mit „zurueckgerollt auf 0.33.0“, `.env` byte-gleich der alten; `docker-compose.yml` 0444 (Tausch, `:514`) → Exit 0, Compose-Marker 0.34.0; der docker-Stub nimmt der `.env` beim `compose up` das Schreibrecht (neuer Schalter nach dem Muster von `AH_TEST_UP_FAIL_ONCE`), `AH_TEST_HEALTH=1` (Rollback nach dem Deploy, `:604`) → Exit ≠ 0 mit „zurueckgerollt“, Pins 0.33.0. Der Kopfkommentar von `update_test.sh` nennt die Fälle. Bestehende Fälle bleiben unverändert grün.
