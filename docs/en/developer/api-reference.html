Developer Guide

API Reference

All HTTP endpoints of the AdminHelper server. Base URL: https://<host>. The complete OpenAPI schema lives at /api/docs (Swagger UI) and /openapi.json.

Authentication

Three mechanisms, depending on the caller:

  • JWT bearer (web panel, desktop): Authorization: Bearer <access_token>. Access and refresh tokens come in the JSON body; for browsers the server additionally sets the refresh token as an HttpOnly cookie (Secure; SameSite=Strict, path /api/auth) – desktop/CLI clients keep sending it in the body. Browser requests, recognised by the Sec-Fetch-Site header, get the refresh token only as the HttpOnly cookie; refresh_token in the body is then "". Desktop, CLI and scripts (without that header) are unchanged.
  • API key (agents, third parties): header X-API-Key. Permission is read or read_write.
  • Internal key (service to service only, monitoring → server): header X-Internal-Key carrying the shared secret MONITOR_API_KEY.

The OpenAPI schema declares all three as security schemes (HTTPBearer, ApiKey, InternalKey); the Swagger UI offers them under “Authorize”.

Where two methods are accepted (connections, FRP provisioning: /api/connections, /api/frp/provision), every credential a request sends must be valid, otherwise 401 – even when the other one is valid. Sent means a non-empty X-API-Key or ?api_key= and any Authorization header but Basic: Basic from a proxy or from user:pass@ in a sync URL is ignored, any other Authorization header must be a valid bearer – a foreign scheme, an empty or unreadable value gives 401. When both are valid, the API key decides. Routes that accept a JWT only do not evaluate an X-API-Key.

Pagination (list endpoints)

The list endpoints GET /api/servers, GET /api/connections, GET /api/hooks, GET /api/audit plus the monitoring lists (/api/monitoring/checks, /api/monitoring/status, /api/monitoring/alerts) accept optional limit (1–1000) and offset (≥ 0) query parameters and return the pre-pagination total in the X-Total-Count header (the monitoring proxy forwards that header). Without parameters the small lists (servers/connections/hooks) return the full list; GET /api/audit, however, caps at 200 entries without limit because the trail grows unbounded (more via offset).

Timestamps

Timestamps in responses are RFC 3339 in UTC with Z, e.g. 2026-10-05T12:00:00Z – also where the schema types them as string. Exceptions:

  • A connection's lastUsed is a stored string and comes back as it was written – the server itself writes +00:00, a client may set the value freely.
  • lastStartTime/lastCloseTime of GET /api/frp/status are passed through unchanged from frps (e.g. 09-27 10:00:00, without year and zone).
  • The result of POST /api/hooks/{id}/run and /api/hooks/trigger is whatever the script returns.
  • data and statusHistory of GET /api/monitoring/checks/{id}/metrics are VictoriaMetrics series; their values are pairs [epoch, "value"] with the time in Unix seconds.

Auth

POST/api/auth/login

Body: { "username", "password" }. Response: { "access_token", "refresh_token", "token_type" }; for browser requests (header Sec-Fetch-Site) refresh_token is "" and the token is only in the HttpOnly cookie. Login rate limit: 5 failed attempts / 60 s / IP.

POST/api/auth/refresh

Body: { "refresh_token" } or HttpOnly cookie (browsers; the body may then be empty). Rotates both tokens, blacklists the old jti. Response as for login; for browser requests refresh_token is "" and the new token is only in the cookie. Reusing an already-revoked refresh token invalidates all sessions of the affected user chain.

POST/api/auth/logout

Authentication optional. Blacklists a presented access token (bearer) and the refresh token from the body ({ "refresh_token" }) or the HttpOnly cookie, and clears the cookie. Without a bearer the logout only affects the refresh token. The audit log (auth.logout) records the logout only when it revoked a token; the response is 200 either way. The logout deliberately does not check the binding to the client certificate: it only ends the tokens it is given, grants nothing, and also works with a certificate the server no longer accepts.

GET/api/auth/me

Current user; requires a valid access token. Response: { "id", "username", "is_admin", "idle_timeout_minutes" }; idle_timeout_minutes is the number of minutes without input after which the web panel signs out (WEB_IDLE_TIMEOUT_MINUTES, 0 = off).

POST/api/auth/bootstrap

Creates the first admin user via a setup token on first start (status 201). Body: { "token", "username", "password" } – username 3–64 chars, password 8–128 chars. Response: { "access_token", "refresh_token", "token_type" } (same as login, so refresh_token is "" for browser requests). The setup token is written to the WARNING log on first start (hash stored at DATA_DIR/.bootstrap_token) and consumed after a successful bootstrap. The same login rate limit applies (5 failed attempts / 60 s / IP). Once any user exists, the endpoint permanently returns 409 Conflict ("Server already initialised"); if no active token is present it returns 401.

Users

GET/api/users

List all users (admin).

POST/api/users

Create user (admin). Password: SHA-256 prehash → bcrypt. Fires user.created.

PUT/api/users/{id}

Update user (admin). Audit user.updated; detail names the changed fields in this order, separated by , : password when a password was sent, is_admin=true|false with the new value when the admin right changes, and server_ids when the server assignment changes; otherwise detail is null. Fires user.promoted when is_admin changes from false to true.

DELETE/api/users/{id}

Delete user (admin). Fires user.deleted.

GET/api/users/{id}/devices

The user's devices (admin): per device line the kind (desktop, browser), whether it was taken over from before the certificate register (legacy), the revocation with its reason (replaced, self, admin), and the fingerprint and expiry of the newest certificate.

DELETE/api/users/{id}/devices/{device_id}

Revoke one device of the user (admin). Its certificates are refused from now on and cannot be renewed; the other devices stay. Audit device.revoked.

GET/api/users/me/servers

Servers assigned to the current user.

Connections

GET/api/connections

List (read).

POST/api/connections

Create (write). An API key bound to a server may only send a serverId equal to its server, else 403. Mapped fields only in camelCase (serverId, keyPath, trustCert, lastUsed); the snake_case spelling is a 422. Fires connection.created.

PUT/api/connections/{id}

Update (write). Same serverId and camelCase rules as for create; a connection outside a key's binding is a 404. Fires connection.updated.

POST/api/connections/{id}/touch

Sets last_used = now (read).

DELETE/api/connections/{id}

Delete (admin). Fires connection.deleted.

GET/api/connections/export

JSON export (admin).

POST/api/connections/import

Body: { "mode": "replace"|"merge", "connections": […] } (admin). All or nothing: an invalid entry or an unknown serverId rejects the whole import with 422, in the form the schema declares: detail[] with one item per error, loc = ["body", "connections", <index>, <field>], in import order. Fires connections.imported.

Servers

GET/api/servers

Server inventory (admin).

GET/api/servers/summary

Only id, name and hostname per server, sorted by name, for the server assignment in the user dialog (admin).

POST/api/servers

Create (admin). The server trims whitespace at the ends of name before checking it (strip()), in the PUT as well. A control character (U+0000 to U+001F, U+007F to U+009F), a lone surrogate (U+D800 to U+DFFF) or the sequence {{ in name → 422, in the PUT as well; frp reads {{ in a config file as the start of a template, a single { and }} stay allowed. Fires server.created.

GET/api/servers/{id}
PUT/api/servers/{id}

Update (admin). Fires server.updated.

DELETE/api/servers/{id}

Delete (admin). Also triggers cleanup at the monitoring service.

Audit

GET/api/audit

Append-only audit trail (admin), newest first, paginated (limit/offset, X-Total-Count). Optional filters: action, actor_type, object_type, object_id, status, q (free-text on actor/object label). There are deliberately no write endpoints.

Hooks

GET/api/hooks
POST/api/hooks

Body: { name, hook_type: "webhook"|"event"|"schedule", event_triggers?: [...], schedule_interval?, script, enabled }. For webhook the token is generated server-side (returned once).

GET/api/hooks/{id}
PUT/api/hooks/{id}

Takes the fields sent; "description": null clears the description, a missing field leaves it as it is.

DELETE/api/hooks/{id}

Auto-removes from the scheduler if it was a schedule hook.

POST/api/hooks/{id}/toggle

Enable/disable; updates scheduler registration.

POST/api/hooks/{id}/rotate

Rotate webhook token.

POST/api/hooks/{id}/run

Manual test run. In the context payload, headers, params and event_data are empty and event_type is null; it also carries triggered_at (now) and last_run (the last scheduled run in UTC with Z, otherwise null).

POST/api/hooks/trigger with an X-Hook-Token header (preferred – keeps the token out of access logs/history), or /api/hooks/trigger/{token} (token in path)

Public (no JWT). Rate limit: 20 req / 60 s / IP. Context: { payload, headers, params }. A NUL byte or a lone surrogate (U+D800 to U+DFFF; JSON spells both only as an escape, \u0000 or e.g. \ud800) in a string or key of the JSON body → 422 with its place in loc, and the script does not run; checked after the rate limit, the token and the enabled state.

Audit: POST /api/hooks writes hook.created (detail type=<hook_type>), PUT and /toggle write hook.updated (detail the changed fields, enabled with its new value, e.g. script, enabled=false), DELETE writes hook.deleted, /rotate hook.token_rotated and /run, after the run, hook.run with status success or failure; no token, no script and no error text of a run lands in the entry, and the trigger and the GET routes write nothing.

FRP – Server Config

GET/api/frp/server-config
POST/api/frp/server-config

Also writes frps.toml into the shared volume. bind_port, vhost_https_port and dashboard_port lie in the range 1 to 65535, max_ports_per_client is at least 0 (0 or null: default 16); a value outside → 422. A dashboard_port equal to 443, to bind_port (7000 without it) or to FRP_BIND_PORT → 422 on dashboard_port, since frps does not take such a configuration over. extra_config takes only the keys transport.maxPoolCount, transport.tcpMux, transport.tcpMuxKeepaliveInterval, transport.heartbeatTimeout, transport.tcpKeepalive, userConnTimeout, log.level and log.maxDays, with true, false, a finite number or a string without quotes, backslashes, braces and control characters; any other key or value → 422. { or } in subdomain_host, dashboard_user, dashboard_password or auth_token → 422, and so does the sequence {{ in name or server_addr (a single { and }} stay allowed there). A control character (U+0000 to U+001F, U+007F to U+009F) or a lone surrogate (U+D800 to U+DFFF; JSON spells it only as an escape, e.g. \ud800) in a text field or an extra_config value → 422.

GET/api/frp/server-config/{id}

Always includes the config’s tunnels (tunnels).

PUT/api/frp/server-config/{id}

Applies only the fields sent, with the same bounds and rules as POST (a value outside → 422). An explicit "bind_port": null → 422; if the field is left out, the value stays. null for vhost_https_port or dashboard_port turns the port off. If the PUT sends dashboard_port or bind_port, the dashboard port rule of POST holds for the state after the update, with the bind port frps gets (a stored bind_port that is null or outside 1 to 65535: 7000): → 422 on the field sent (dashboard_port, else bind_port), and nothing of the update is stored. Without either field, a port of that kind already stored stays untouched. An auth_token of null or "" leaves the stored token unchanged; a new one needs at least 16 characters besides whitespace at the start and end, otherwise → 422.

DELETE/api/frp/server-config/{id}

FRP – Tunnels

GET/api/frp/tunnels

Query: ?server_id, ?frp_config_id. Tunnel responses carry secretKey as null – here, in /api/frp/status, /api/frp/server-config/{id} and /api/servers (frpTunnels). The secret is only in the generated TOML files (/api/frp/generate/*) and in provisioning (/api/frp/provision/{server_id}/config). An admin gets every tunnel in this shape, a non-admin only the enabled tunnels of the servers assigned to him, each with just id, serverId, name, tunnelType, protocol, localPort, visitorPort, customDomains, connectionId and enabled (what the desktop reads); [] without an assigned server, the query parameters only narrow this down. The other tunnel routes: non-admin → 403.

POST/api/frp/tunnels

STCP (with secret_key, visitor_port) or HTTPS (custom_domains); an HTTPS tunnel stores neither secret nor visitor port, values sent along are dropped. visitor_port is a port from 1 to 65535; if it is left out or null, the server assigns a free one to an STCP tunnel. Any other value, 0 included, → 422, for an HTTPS tunnel as well. local_port is a port from 1 to 65535, any other value → 422. auto_create_connection=true also creates a matching connection. A control character (U+0000 to U+001F, U+007F to U+009F), a lone surrogate (U+D800 to U+DFFF) or the sequence {{ in name, local_ip, secret_key, custom_domains, auto_connection_username or an extra_config value → 422, in the PUT as well; a single { and }} stay allowed. An extra_config key consists of segments of A-Z a-z 0-9 _ -, separated by a single . (so not .a, a. or a..b); regardless of case it may neither equal a field the server writes into the proxy (name, type, localIP, localPort, secretKey, allowUsers, customDomains) nor another key, nor be a prefix of one or have one as a prefix (such as localport, localIP.x, foo next to FOO); an integer lies between -263 and 263-1. Otherwise 422, in the PUT as well. A key whose first segment is plugin, in upper or lower case (such as plugin, plugin.type or PLUGIN.type), → 422, in the PUT as well: the server sets up no proxy plugins, and the agent does not apply a frpc.toml with such a key (see Agent). A connection_id no connection matches gives 422.

GET/api/frp/tunnels/{id}
PUT/api/frp/tunnels/{id}

A secret_key of null or "" keeps the stored secret; if the tunnel becomes STCP without a secret, the server generates one. Switching to HTTPS deletes secret and visitor port; switching back to STCP generates a new secret (unless one is sent) and assigns a free port if the stored one has been taken meanwhile or lies outside 1 to 65535. A taken port sent explicitly stays 409. "visitor_port": null assigns a free port to an STCP tunnel. A visitor_port outside 1 to 65535, 0 included, → 422, and nothing of the update is stored. A local_port outside 1 to 65535, null included, → 422. A connection_id no connection matches gives 422.

DELETE/api/frp/tunnels/{id}

FRP – Generate (TOML/ZIP)

GET/api/frp/generate/frps-toml?config_id=…
GET/api/frp/generate/frpc-toml/{server_id}

404 if the server has no active, usable tunnel; an STCP tunnel without a secret does not count, nor does a stored tunnel with a local_port outside 1 to 65535, with characters the API refuses today (such as quotes, backslash, control characters, {{) in its name, local_ip, custom_domains or secret_key, or whose extra_config carries a key of the plugin family (first segment plugin) or another entry the API refuses today; the frpc.toml leaves such a tunnel out.

GET/api/frp/generate/visitor-toml?config_id=…&user_id=…

404 if no usable STCP tunnel is visible, also when the visible ones have no secret, no visitor port from 1 to 65535 or stored characters the API refuses today (such as quotes, backslash, control characters, {{) in its name, local_ip, custom_domains or secret_key: no tunnel, no auth.token. The TOML leaves such a tunnel out.

GET/api/frp/generate/visitor-bundle?config_id=…

Returns { toml, pki }; 404 as for visitor-toml.

GET/api/frp/generate/bulk-zip?config_id=…

ZIP with frps.toml + clients/*.toml + visitors/*.toml — only for servers and users with a usable tunnel (an STCP tunnel without a secret or with stored characters the API refuses today (such as quotes, backslash, control characters, {{) in its name, local_ip, custom_domains or secret_key does not count, for clients/*.toml neither does one with a local_port outside 1 to 65535 or whose stored extra_config carries a key of the plugin family or another entry the API refuses today, and for visitors/*.toml neither does one without a visitor port from 1 to 65535).

Server provisioning (FRP-independent, since v0.23.2)

POST/api/servers/{server_id}/provision/token

Admin-only (JWT). Returns { token, expiresAt, serverId, serverName } – one-time, 24 h TTL. Audit provision.token.minted with the server as object and detail ttl=24h; neither the token nor its hash is in the entry.

GET/api/servers/{server_id}/provision/tokens
POST/api/servers/{server_id}/provision/activate

Header X-Provision-Token. Response: { serverName, apiKey, monitorApiKey?, monitorUrl?, frp?, enrollment }. apiKey is always the one-time generated server read API key. monitorApiKey/monitorUrl are null when the monitor service is unreachable; frp is null without an FRP config and otherwise has { config, pkiBundle } — config is the frpc.toml (Base64), the same text as GET /api/frp/provision/{server_id}/config: with no active FRP tunnel on the host it has no tunnel and no frps credentials (see config-hash); pkiBundle is always "" since A7 (the agent enrolls its tunnel cert itself). enrollment = { token, subjectId, scope:"tunnel", enrollPort }: the one-time token with which the agent fetches its mTLS cert from the ca-issuer (A4). Activation deletes the API keys of earlier provisionings of this server (audit apikey.deleted); only the new one counts.

POST/api/enrollment/token

JWT-gated, self-service: a logged-in user registers a further own device without an admin. Under MTLS_ENFORCE=true (the default) only a device with a valid client certificate reaches the endpoint; a device without a certificate registers with a token from /token/for. Mints a one-time, access-scoped enrollment token for the logged-in user (CN = username). Query ?browser=true → a long-lived leaf for the desktop's browser-P12 export (A5). Audit enrollment.token.minted with (self); with browser=true it notes, as /token/for does, the long-lived leaf that is revocable only under MTLS_ENFORCE=true. Response: { token, subjectId, scope, enrollPort, browser, expiresAt }; expiresAt is the token's stored expiry in UTC with Z (always 10 minutes here).

POST/api/enrollment/token/for

Admin only. Mints an enrollment token for another, already-existing identity (body { username, browser?, ttl_minutes? }) — the decoupled enrollment door (ADR 0003): under enforced mTLS an admin hands the token over out-of-band and the new user redeems it certless at :8444. CN = the target username (issuer-dictated). ttl_minutes is the token's validity in minutes, 1 to 1440 (24 h), default 10; a value outside → 422. Audit enrollment.token.minted_for names the validity (e.g. browser=False, ttl=60min). Unknown user → 404, non-admin → 403. Response as above, expiresAt with the chosen validity.

POST/api/enrollment/self/revoke

The calling device revokes itself: the device line of the client certificate of this request. The certificate (mTLS) is the proof, no JWT. 204; in permissive mode without a verified certificate 409 (enforced, the scope check already rejects a request without a certificate); a certificate already revoked gets 403 ERR_CERT_REVOKED.

FRP – sync (running operation)

GET/api/frp/provision/{server_id}/config

Current frpc.toml plain text (JWT or API key) – only for the running sync. Without an active tunnel on the host it is the common part without a tunnel and without the frps credentials (no auth.token); without an FRP config 404.

GET/api/frp/provision/{server_id}/config-hash

SHA-256 of the frpc.toml for drift-free synchronisation: { hash }, without an active tunnel on the host too the hash of exactly the text GET …/config then serves. Active means enabled, and for STCP only with a secret – exactly the tunnels the frpc.toml lists as [[proxies]]; provisioning returns the same text in frp.config. Without an FRP config hash is null instead of an error (nothing to sync), and GET …/config answers 404.

FRP – Status

GET/api/frp/status

Merges the frps dashboard with DB tunnels.

GET/api/frp/supervisor-status

Admin only. State of the frps supervisor from its status file, codes, times and a flag only: { state, reason, since, stale, lastEvent, lastEventAt, publishedBindPort }. state is waiting, running, degraded, stopped or crashloop; missing while there is no status file, and unreadable when it does not match the expected format – then reason and since are null. reason is none, config_missing, token_invalid, tls_not_forced, cert_paths, cert_missing, cert_expired, cert_key_mismatch, verify_failed, input_unreadable (an input file is there but cannot be read, is no regular file, is a symlink or is larger than 1 MiB), input_unstable (the input keeps changing over several polls and is not taken over until it stays the same) or processes_left (processes of the frps user could not be ended; frps does not start until the input changes or the container restarts). lastEvent and lastEventAt are the newest event (started, applied, rejected, stopped, crashed, copy_changed: the checked copy frps starts from changed after it was taken over and was dropped, or start_refused: frps was not started, the cause as in reason) and its time, null without an event. stale is true when the supervisor's last heartbeat is older than 60 s. publishedBindPort is the host port compose publishes for frps (FRP_BIND_PORT, default 7000). Non-admin → 403.

The former /api/frp/pki/* endpoints (CA/cert generation) have been removed – the server no longer signs certificates (D6); the FRP TLS material comes exclusively from the ca-issuer.

Monitoring (reverse proxy)

POST/api/monitoring/agent/{server_id}/report

Public (X-API-Key). Forwards the agent push 1:1 to the monitoring microservice.

GET/api/monitoring/{path:path}

Admin-only reverse proxy. Allowed path prefixes: checks, alerts, status, templates, maintenance, agent. Path traversal is blocked. If the monitoring service cannot be reached, the proxy answers 502, with no answer within 30 s 504.

POST/api/monitoring/{path:path}
PUT/api/monitoring/{path:path}
DELETE/api/monitoring/{path:path}

Audit: every POST, PUT and DELETE the monitoring service answers writes monitoring.post, monitoring.put or monitoring.delete with object_type monitoring, the forwarded path (encoded, without query) as object_label, detail status=<HTTP status> and status success (below 400) or failure. If forwarding breaks off after sending (e.g. a read timeout), the same entry is written with status error and detail error=<type name>; a connection error (nothing sent), a rejected path, GET and the agent report write nothing. The request content never lands in the entry.

No dedicated alerts or settings endpoints on AdminHelper

Alerts and check status come through the monitoring proxy from the separate service.

Notifications (since v0.38.0)

GET/api/notifications

The caller's bell feed, newest first. Query: unread_only (bool, default false), limit (1–1000), offset (≥0). Returns a list of notification objects.

GET/api/notifications/unread-count

Cheap badge count for the bell. Returns { "count" }.

POST/api/notifications/read

Mark notifications read. Body: { "ids": […] } – omitting ids / null marks all read.

GET/api/notifications/stream

Server-Sent Events (text/event-stream): pushes a “refresh” nudge whenever the user gets a new notification (push, not polling). Cross-worker via Redis Pub/Sub. The gateway proxies the stream unbuffered with a long read timeout; a heartbeat comment keeps it open and the auth (JWT/mTLS) is re-validated periodically.

GET/api/users/me/notification-prefs

The caller's subscription rules + contact data.

PUT/api/users/me/notification-prefs

Replace-all: sets email/telegram_chat_id (verbatim, null clears) and rewrites the subscription set. Each subscription: scope_type (all/tag/server), scope_ref, min_severity (default warning), optional categories filter.

POST/api/internal/events

Internal only (header X-Internal-Key): event ingress for the monitoring→hub path. Body: { "event_type", "severity", "category", … }. Fans the event out to matching recipients. Status 202, returns { "notified" }. A bundled event names its servers in source_ids (1–500 server ids, each 1–256 characters) instead of source_id; both together give 422. The source_type values frp_config and frps are reserved for notices of the server itself and give 422. Each recipient gets one row about the servers they may see: title <title> (<n>), text body plus one line per server. title and body therefore name no server and carry no total – the server appends count and names per recipient. A bundled event fires the alert.triggered hook once per server.

Error Format

json
HTTP/1.1 422 Unprocessable Entity
Content-Type: application/json

{
  "detail": [
    { "loc": ["body", "port"], "msg": "ensure this value is less than 65536", "type": "value_error" }
  ]
}

Errors follow Pydantic validation conventions. When a 422 echoes input with a lone surrogate, its body writes every character outside ASCII as a JSON escape (\uXXXX).

An error a client is meant to react to carries the field code next to detail: stable, of the form ERR_…. detail stays text and, for compatibility, starts with <code>: ; the wording after it may change. Today the 403 of the certificate check carry a code: ERR_CERT_REVOKED (certificate revoked or not recorded), ERR_CERT_USER_MISMATCH (certificate of another user), ERR_CERT_SERVER_MISMATCH (agent certificate of another server). Clients branch on code, never on the text. Every other error has no code.

json
HTTP/1.1 403 Forbidden
Content-Type: application/json

{
  "detail": "ERR_CERT_REVOKED: This device certificate is no longer valid. Reset the device identity and register the device again.",
  "code": "ERR_CERT_REVOKED"
}

Rate Limits

  • Login: 5 failed attempts / 60 s / IP (Redis with in-memory fallback).
  • Webhook trigger: 20 requests / 60 s / IP.
  • Agent push: not throttled, but every request must match its own server_id via X-API-Key.
Use Swagger directly

/api/docs renders OpenAPI 3.1 interactively, including "Try it out". For CI clients, a single openapi-generator generate -g go -i https://srv/openapi.json is enough.
